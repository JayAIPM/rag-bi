# 项目架构文档

本项目为整个 RAG 大项目的后端服务部分，不涉及前端，不涉及 AI 模型层。
文档中之所以提到前端和 AI 模型层的功能说明仅为加强对 RAG 项目整体把控。
以上信息非常关键，务必谨记！

## 1. 项目概述

项目名称：RAG-Backend
项目类型：本地部署的企业级 RAG 知识库系统的后端服务
项目目标：前后端分离架构，本项目负责整个 RAG 项目中的后端服务部分，**全链路基于 Node.js 生态开发，零 Python 环境依赖，优先原生 javascript 语言开发，次选 ts**，支持本地私有化部署，开箱即用，兼顾 POC 演示与生产级落地需求。

### 1.1 整体 RAG 项目核心功能概述

| 功能模块       | 核心能力                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------- |
| 数据接入与治理 | 多格式文档（PDF/Word/Excel/PPT/TXT/MD）解析、OCR 扫描件识别、语义父子分块、数据清洗归一化、增量同步、版本管理 |
| 多策略检索引擎 | 向量+BM25 混合检索、重排序精排、智能查询重写、复杂问题拆解、权限前置过滤、反馈闭环优化                        |
| 可控生成与合规 | 幻觉抑制、事实锚定、引用溯源、企业话术管控、输入输出内容安全审核、全链路审计日志                              |
| 企业级权限管控 | RBAC 角色管理、SSO 单点登录预留、文档级/片段级细粒度权限、组织架构数据隔离、敏感数据脱敏                      |
| 问答交互       | 多轮对话、流式响应、引用原文对照、回答反馈纠错、对话历史管理                                                  |
| 运营与可观测   | 可视化运营仪表盘、高频问题统计、检索命中率监控、效果评估、全链路故障排查                                      |
| 扩展集成       | 全量 RESTful API 开放、WebHook 预留、RAG+Agent 工具调用预留、多模型无缝切换                                   |

---

### 1.2 核心亮点

1. **纯 Node.js 技术栈**：零 Python 依赖，从服务端、RAG 引擎到向量数据库全链路基于 JS/TS 实现，完美适配 Node.js 开发技术栈
2. **企业级能力全覆盖**：对齐 2026 年行业生产级标准，内置语义分块、混合检索、重排序、引用溯源、权限管控、全链路审计等核心能力
3. **完全本地化部署**：基于 Ollama 运行开源大模型，所有数据、模型、服务均本地运行，无数据泄露风险，适配企业私有化需求
4. **前后端分离架构**：Express.js RESTful API 后端 + Vue3 前端，解耦开发，易于扩展与二次开发
5. **轻量易部署**：支持本地一键启动，同时提供 Docker 容器化部署方案，兼顾开发调试与生产环境落地
6. **可观测可运营**：内置运营仪表盘、全链路日志、效果评估体系，支持持续迭代优化

## 📖 API 接口概览

所有接口统一前缀：`/api/v1`

### 核心接口列表(未列出全部，需要根据项目实际需求进一步补充和完善)

| 接口路径           | 请求方法 | 接口描述                          | 权限要求     |
| ------------------ | -------- | --------------------------------- | ------------ |
| `/auth/login`      | POST     | 用户登录获取 Token                | 无           |
| `/auth/user-info`  | GET      | 获取当前用户信息与权限            | 登录用户     |
| `/knowledge`       | GET      | 获取有权限的知识库列表            | 登录用户     |
| `/knowledge`       | POST     | 创建知识库                        | 管理员       |
| `/document`        | POST     | 上传文档并触发向量化入库          | 知识库管理员 |
| `/document/{id}`   | DELETE   | 删除文档与对应向量数据            | 知识库管理员 |
| `/chat/ask`        | POST     | 发送问题，触发 RAG 全流程返回回答 | 登录用户     |
| `/chat/history`    | GET      | 获取用户对话历史                  | 登录用户     |
| `/stats/dashboard` | GET      | 获取运营仪表盘核心指标            | 管理员       |

## 📐 开发规范

1.  **代码规范**：遵循 ESLint 规范，使用 Prettier 格式化代码，保持代码风格统一
2.  **Git 提交规范**：采用`feat: 新增功能`/`fix: 修复bug`/`docs: 文档更新`等规范格式
3.  **接口规范**：严格遵循 RESTful API 设计规范，统一响应格式，完善参数校验
4.  **安全规范**：所有接口必须做权限校验，敏感数据脱敏，输入内容做安全过滤
5.  **日志规范**：全操作必须留存日志，错误日志必须包含完整上下文，便于排查问题
