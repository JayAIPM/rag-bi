# 项目架构文档

本项目为整个 RAG 大项目的后端服务部分，不涉及前端，不涉及 AI 模型层。
文档中之所以提到前端和 AI 模型层的功能说明仅为加强对 RAG 项目整体把控。
以上信息非常关键，务必谨记！

## 1. 项目概述

项目名称：RAG-Backend
项目类型：本地部署的企业级 RAG 知识库系统的后端服务
项目目标：前后端分离架构，本项目负责整个 RAG 项目中的后端服务部分，**全链路基于 Node.js 生态开发，零 Python 环境依赖，优先原生 javascript 语言开发，次选 ts**，支持本地私有化部署，开箱即用，兼顾 POC 演示与生产级落地需求。

### 1.1 整体 RAG 项目核心功能概述

| 功能模块       | 核心能力                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------- |
| 数据接入与治理 | 多格式文档（PDF/Word/Excel/PPT/TXT/MD）解析、OCR 扫描件识别、语义父子分块、数据清洗归一化、增量同步、版本管理 |
| 多策略检索引擎 | 向量+BM25 混合检索、重排序精排、智能查询重写、复杂问题拆解、权限前置过滤、反馈闭环优化                        |
| 可控生成与合规 | 幻觉抑制、事实锚定、引用溯源、企业话术管控、输入输出内容安全审核、全链路审计日志                              |
| 企业级权限管控 | RBAC 角色管理、SSO 单点登录预留、文档级/片段级细粒度权限、组织架构数据隔离、敏感数据脱敏                      |
| 问答交互       | 多轮对话、流式响应、引用原文对照、回答反馈纠错、对话历史管理                                                  |
| 运营与可观测   | 可视化运营仪表盘、高频问题统计、检索命中率监控、效果评估、全链路故障排查                                      |
| 扩展集成       | 全量 RESTful API 开放、WebHook 预留、RAG+Agent 工具调用预留、多模型无缝切换                                   |

---

### 1.2 核心亮点

1. **纯 Node.js 技术栈**：零 Python 依赖，从服务端、RAG 引擎到向量数据库全链路基于 JS/TS 实现，完美适配 Node.js 开发技术栈
2. **企业级能力全覆盖**：对齐 2026 年行业生产级标准，内置语义分块、混合检索、重排序、引用溯源、权限管控、全链路审计等核心能力
3. **完全本地化部署**：基于 Ollama 运行开源大模型，所有数据、模型、服务均本地运行，无数据泄露风险，适配企业私有化需求
4. **前后端分离架构**：Express.js RESTful API 后端 + Vue3 前端，解耦开发，易于扩展与二次开发
5. **轻量易部署**：支持本地一键启动，同时提供 Docker 容器化部署方案，兼顾开发调试与生产环境落地
6. **可观测可运营**：内置运营仪表盘、全链路日志、效果评估体系，支持持续迭代优化

### 核心模块划分

| 模块名称 | 核心职责 | 技术实现 |
| --- | --- | --- |

| 检索引擎模块 | 向量检索、BM25 检索、混合检索、重排序 | LlamaIndex.TS + LanceDB |
| 对话管理模块 | 多轮对话、流式响应、引用溯源、对话历史 | Express.js + MongoDB |

| 日志管理模块 | 请求日志、错误日志、业务日志记录 | Winston + DailyRotateFile |

### 分层架构

1. **控制层（Controller）**：处理 HTTP 请求，参数验证，响应返回
2. **服务层（Service）**：业务逻辑处理，协调各模块功能
3. **数据访问层（DAO）**：数据库操作，数据持久化
4. **工具层（Utils）**：通用工具函数，如加密、日志、文件处理等
5. **模型层（Model）**：数据模型定义，数据库表结构映射
6. **中间件层（Middleware）**：认证、权限验证、日志记录、错误处理

### MVC 架构规范

- **Router 层**：定义 URL 路径和 HTTP 方法，将请求转发给 Controller
- **Controller 层**：处理请求和响应，调用 Service 层方法，通过 next(err) 抛出错误
- **Service 层**：收敛业务逻辑，处理数据库操作，抛出带有状态码的错误
- **Model 层**：定义数据结构，提供数据访问方法
- **中间件**：处理全局错误和其他横切关注点

### 错误处理规范

- 使用 `express-async-errors` 自动捕获 async 函数中的错误，避免在每个 Controller 中手动写 try-catch
- Service 层抛出的错误应包含 `statusCode` 属性，以便全局错误处理中间件正确处理
- 全局错误处理中间件统一处理所有错误，返回标准化的错误响应
- 验证错误由验证中间件统一处理，返回清晰的错误信息

### 接口响应格式规范

- 所有接口返回格式统一为：`{ code, msg, data }`
- 成功响应：`code = 0, msg = 'success', data = 具体返回数据`
- 错误响应：`code = 状态码（如 400, 401, 500 等）, msg = 错误描述, data = null`
- 确保所有接口遵循此格式，便于前端统一处理

### 数据流

1. **文档处理流程**：文档上传 → 格式解析 → OCR 识别 → 语义分块 → 向量化 → 存储到 LanceDB → 元数据存储到 MongoDB
2. **对话流程**：用户提问 → 权限验证 → 智能查询重写 → 混合检索 → 重排序 → 上下文构建 → LLM 生成回答 → 引用溯源 → 返回结果 → 对话历史存储

## 📋 核心流程设计

> 详细实现状态请参考 [development-plan.md](development-plan.md#模块划分与任务分解)

### 文档处理流程

1. **文档上传** ✅：用户通过 API 上传文档，支持多种格式
2. **格式解析** ✅：解析不同格式的文档，提取文本内容
3. **OCR 处理** ⏸️：对扫描件和图片进行 OCR 识别（未实现）
4. **语义分块** ✅：基于 SentenceSplitter 进行智能分块
5. **向量化处理** ✅：使用 Ollama 嵌入模型将文本转换为向量
6. **存储** ✅：向量存储到 LanceDB，元数据存储到 MongoDB
7. **索引更新** ✅：更新知识库索引，确保检索的实时性

### 对话流程

1. **用户提问** ✅：用户发送问题到 API
2. **权限验证** ✅：验证用户是否有权限访问指定知识库
3. **智能查询重写** ⏸️：优化用户查询，提高检索效果（后续迭代）
4. **混合检索** ✅：结合向量检索和 BM25 检索，获取相关文档片段
5. **重排序** ⏸️：使用重排序模型对检索结果进行二次排序（后续迭代）
6. **上下文构建** ✅：构建 LLM 上下文，包含检索结果和对话历史
7. **LLM 生成** ✅：调用本地 Ollama 模型生成回答，流式响应
8. **引用溯源** ⏸️：在回答中添加原文引用，提高可信度（后续迭代）
9. **返回结果** ✅：流式返回回答结果
10. **对话历史** ✅：保存对话历史到 MongoDB

### 权限控制流程

1. **用户登录** ✅：用户提供 credentials，获取 Token
2. **Token 验证** ✅：每次请求验证 Token 有效性
3. **权限检查** ✅：根据用户角色和权限列表，检查是否有权限执行操作
4. **资源访问控制** ✅：检查用户是否有权限访问指定资源

## 🔒 安全措施

1. **认证授权**：基于 JWT 的认证机制，严格的权限检查
2. **数据加密**：敏感数据加密存储，HTTPS 传输
3. **安全审计**：全链路操作审计日志，便于追溯
4. **输入验证**：严格的输入验证，防止注入攻击
5. **内容安全**：输入输出内容的安全审核，防止有害内容
6. **Token 管理**：同一用户仅能存在一个有效 Token，避免令牌泄露
7. **RBAC 权限控制**：基于角色的访问控制，支持细粒度权限管理

### JWT 令牌使用方式

1. **获取令牌**：通过登录接口 `POST /api/v1/auth/login` 获取 JWT 令牌（有效期 24h）
2. **携带令牌**：在请求头中添加 `Authorization` 字段，格式为 `Bearer <token>`
3. **访问受保护资源**：使用携带令牌的请求访问需要认证的接口，如 `GET /api/v1/auth/user-info`
4. **登出**：通过登出接口 `POST /api/v1/auth/logout` 使令牌失效

示例请求：
```bash
# 登录获取令牌
curl -X POST http://localhost:3000/api/v1/auth/login -H "Content-Type: application/json" -d '{"username": "admin", "password": "admin123"}'

# 使用令牌访问受保护资源
curl -X GET http://localhost:3000/api/v1/auth/user-info -H "Authorization: Bearer <token>" 

# 登出
curl -X POST http://localhost:3000/api/v1/auth/logout -H "Authorization: Bearer <token>" 
```
